# Bitfinex 綠葉放貸機器人 🍃

自動化 Bitfinex funding(放貸)掛單,部署在 GitHub Actions 上長期免費執行,
每 15 分鐘依市場實際成交價重新定價一次。

---

# 掛單策略

## 一、每輪執行流程

每 15 分鐘執行一次,依序做五件事:

1. **讀市場**:抓 ticker(FRR、訂單簿最佳報價)與全市場最近 1000 筆**實際成交**紀錄
2. **清掉過時掛單**:低利率單掛滿 30 分鐘就取消重新定價;高利率單給 240 分鐘耐心(見「四、續借」)
3. **算可掛資金**:funding 錢包可用餘額 − `reserve_amount`
4. **決定階梯**:利率鋪在真實成交帶上(見「二」),資金拆成多筆(見「三」),依利率決定放貸天數(見「四」)
5. **送出掛單**

任一幣別失敗會以非零狀態碼結束,GitHub Actions 顯示紅燈,錯誤內容也會進儀表板。

## 二、利率怎麼定 —— 錨定「實際成交帶」

這是整套策略最關鍵的一點。市場上有三個看起來都能當基準的數字,但**只有一個是對的**:

| 數字 | 是什麼 | 為什麼不能用 |
|---|---|---|
| **ASK**(訂單簿最低報價) | 底層殺價最兇的掛單 | 跟著掛等於當全市場最便宜的錢,**瞬間被吃掉且只拿到約半價** |
| **FRR** | 已提供資金的加權平均,含過去在尖峰鎖進去的長天期高利單 | **系統性地是真實清算價的兩倍**,掛上去幾乎永遠不會成交 |
| **實際成交價** ✅ | 全市場最近真正成交的利率分布 | — 這才是「現在確實借得出去的價格」 |

### FRR 不可用的實證

近 250 小時(10.4 天)逐時比對「當時 FRR」與「當時實際成交價」:

| 檢驗項目 | 結果 |
|---|---|
| 收盤成交價 ≥ 當時 FRR 的小時數 | **0 / 250 = 0.0%** |
| 該小時最高成交價 ≥ FRR 的小時數 | 7 / 250 = 2.8% |
| 成交價 / FRR 的中位比值 | **0.487** |
| FRR 中位 vs 實際成交中位 | 0.0309%/日 vs **0.0150%/日** |

回測掛在不同利率的期望年化(掛不掉的資金以 0 收益計):

| 掛單利率 | 名目 APR | 成交小時佔比 | 期望實現年化 |
|---|---|---|---|
| 0.0140% | 5.11% | 100.0% | 5.11% |
| **0.0180%** | **6.57%** | **88.8%** | **5.83% ← 最佳** |
| 0.0220% | 8.03% | 70.4% | 5.65% |
| 0.0260% | 9.49% | 33.2% | 3.15% |
| 0.0309%(FRR) | 11.26% | 4.4% | **0.48%** |

所以 `min_daily_rate_pct` 設在回測最佳點 **0.018%/日**。
**追求「年化維持在 FRR 之上」是結構性做不到的** —— 那等於要求永遠不成交。

### 階梯的上下界

- **下界** = 最近成交價的第 `market_anchor_percentile`(25)分位,並且不低於 `min_daily_rate_pct`
  取分位而非平均:成交價分布集中時,25 分位讓第一層幾乎必定成交,只犧牲極小利率,
  換到的資金使用率遠高於掛在均價之上空等
- **上界** = 第 `market_top_percentile`(90)分位,若「續借利率」更高則取續借利率(見「四」)

階梯在上下界之間**線性鋪開**,所以寬度由市場自己決定:

- 市場窄幅 → 階梯自動收窄,每層都掛得掉
- 行情波動、成交價拉開 → 階梯自動變寬,高層才有機會吃到尖峰

這比寫死的百分比步幅(`ladder_step_pct`)穩健得多;後者只在**取不到成交紀錄**時當退路使用。

## 三、金額怎麼拆 —— 隨餘額自動調整

```
n = min(num_ladder_steps, 可用資金 ÷ min_offer_size)   ← 每筆不低於交易所最小額
n = max(n, ⌈可用資金 ÷ max_offer_size⌉)                ← 每筆不超過單筆上限
n = max(1, min(n, 可用資金 ÷ min_offer_size))          ← 防呆:上限誤設過小時仍守住最小額
每筆金額 = 可用資金 ÷ n（等分,尾差歸最後一筆）
```

實際分配(min 150 / max 5000 / 4 層):

| 可用餘額 | 拆成 | 每筆金額 |
|---|---|---|
| 100 | 不掛單 | 低於交易所最小額 150 |
| 160 | 1 筆 | 160 |
| 320 | 2 筆 | 160 × 2 |
| 623 | 4 筆 | 156 × 4 |
| 1,500 | 4 筆 | 375 × 4 |
| 6,000 | 4 筆 | 1,500 × 4 |
| 25,000 | 5 筆 | 5,000 × 5 |
| 120,000 | 24 筆 | 5,000 × 24 |

**不會出現「不足最小額的零頭單」** —— 先用「資金 ÷ 150」決定筆數再等分,每筆天然 ≥ 150;
資金不夠分 4 層就自動減少層數。利息複利讓餘額長大時,掛單金額自動跟著放大,不需手動調整。

## 四、放貸天數與續借

### 利率越高鎖越久(`period_rules`)

| 成交利率 | 放貸天數 | 用意 |
|---|---|---|
| < 0.032%/日(APR 11.7%) | **2 天** | 平常維持短期,兩天後回流可追最新行情 |
| ≥ 0.032%/日(APR 11.7%) | 30 天 | 明顯高於市場,鎖一個月 |
| ≥ 0.045%/日(APR 16.4%) | 120 天 | 真尖峰,把瞬間高利變成四個月固定收益 |

門檻依實際成交分布校準(中位 0.0150、月高約 0.0307),所以**平常不會鎖倉**,
只有行情把利率推到異常高檔才綁住資金。放貸一旦成交就**不能提前收回**,這是刻意保守的設計。

### 高利率續借,低利率重新定價

> **注意**:Bitfinex 沒有可用的單筆續借開關。`auth/w/funding/keep` 對已被借走的 credit
> 回報 `SUCCESS` 但 RENEW 欄位完全不變(空操作),依賴它會讓機器人每輪反覆切換卻永不收斂。
> 因此續借由機器人自己實作。

- **高利率的**:記住近 `renew_lookback_days`(7)天內我們**實際成交過**、且 ≥
  `renew_min_daily_rate_pct`(0.020%/日)的最佳利率,拿它當階梯頂端沿用下去。
  這類掛單享有 `high_rate_stale_minutes`(240 分鐘)的耐心,不會每 30 分鐘就被砍掉重掛
- **低利率的**:照常 `stale_offer_minutes`(30 分鐘)重新定價,緊貼市場

效果等同「好價格的放貸到期後繼續用那個好價格掛出,普通價格的則回歸市場」。

**代價**:高利率單在等待期間不生息,會略微拉低資金使用率。若實現年化因此下降,
調低 `high_rate_stale_minutes` 或調高 `renew_min_daily_rate_pct` 即可收回。

## 五、必須關掉 Bitfinex 原生自動放貸

交易所內建的 Auto-Renew 會用「rate 0(跟隨 FRR)」把整筆餘額掛出,和機器人搶同一筆錢:
機器人把它當過時舊單取消、改掛自己的價,兩套系統互相拆台,資金大量空轉。

本專案已透過 API 關閉(`auth/w/funding/auto`, status=0)。若要重新確認:
掛單紀錄裡不再出現「利率 0.0000%/日」的整筆大額掛單,就表示關乾淨了。

# 設定檔 config.json

所有利率單位都是**每日利率 %**(0.02 = 0.02%/日 ≈ 年化 7.3%)。

| 欄位 | 預設 | 說明 |
|---|---|---|
| `stale_offer_minutes` | 30 | 一般掛單超過幾分鐘未成交就取消重新定價(全域設定) |
| `enabled` | — | 是否啟用該幣別(內建 USD、UST,可自行新增) |
| `min_offer_size` | 150 | 最小掛單金額(Bitfinex 規定 USD/UST 最少 150) |
| `max_offer_size` | 5000 | 單筆掛單上限,資金多時自動拆更多筆 |
| `num_ladder_steps` | 4 | 階梯層數 |
| `market_anchor_percentile` | 25 | 階梯下界取最近成交價的第幾分位(調低→更易成交、利率略低) |
| `market_top_percentile` | 90 | 階梯上界取第幾分位 |
| `min_daily_rate_pct` | 0.018 | 利率地板,低於此寧可不掛(回測最佳點) |
| `renew_min_daily_rate_pct` | 0.020 | 高於此利率的掛單享有續借與耐心等待 |
| `renew_lookback_days` | 7 | 續借利率往回看幾天的自身成交紀錄 |
| `high_rate_stale_minutes` | 240 | 高利率掛單的等待時間 |
| `reserve_amount` | 0 | 保留不掛出的金額 |
| `period_rules` | 見上 | 利率 → 放貸天數對照 |
| `ladder_step_pct` | 3 | **僅**在取不到成交紀錄、退回訂單簿定價時使用的每層遞增幅度 |

## 想調整策略時

| 目標 | 怎麼做 |
|---|---|
| 更快成交、減少空轉 | `market_anchor_percentile` 調低(如 10)、`high_rate_stale_minutes` 調低 |
| 更貪心等高利率 | `market_top_percentile` 調高、`renew_min_daily_rate_pct` 調低 |
| 拒絕低利率行情 | `min_daily_rate_pct` 調高(但過高會大量空轉,參考「二」的回測表) |
| 留一筆錢不放貸 | `reserve_amount` |
| 加開幣別 | 把 `UST` 的 `enabled` 改 `true`,或依相同格式新增 |

# 部署

## 1. 建立 Bitfinex API 金鑰

到 [Bitfinex API Keys](https://setting.bitfinex.com/api) 建立金鑰,權限**只勾**:

- Margin Funding → **Get funding statuses and info**(讀取)
- Margin Funding → **Offer, cancel and close funding**(下單)

⚠️ **不要**勾提領(Withdraw)或交易權限,被盜也偷不走錢。

## 2. 設定 Secrets

GitHub repo → Settings → Secrets and variables → Actions → New repository secret:

| 名稱 | 內容 |
|---|---|
| `BFX_API_KEY` | API Key |
| `BFX_API_SECRET` | API Secret |
| `DASHBOARD_PASSWORD` | 儀表板密碼(見下方) |

> ⚠️ 用 PowerShell 管線寫入 Secrets 會在值前面加上看不見的 BOM,導致 API 簽名失敗。
> 請直接在 GitHub 網頁貼上,或用 Bash。機器人本身已會自動清除金鑰開頭的 BOM 與空白。

## 3. 排程

[.github/workflows/lending-bot.yml](.github/workflows/lending-bot.yml) 設為每 15 分鐘一次。

- **公開 repo**:Actions 分鐘數無上限
- **私人 repo**:每月 2000 免費分鐘 → 請改回 `*/30 * * * *`

## 4. 測試

repo → Actions → Bitfinex Lending Bot → **Run workflow**,勾選 `dry_run` 先跑一次,
確認 log 顯示的掛單計畫合理,再取消勾選正式執行。
